# 别再用“增删选链表”选集合：用浏览历史理解 LinkedList

## 引言与适用环境
“ArrayList 查得快、LinkedList 增删快”省略了决定性能的重要条件：通过什么方式找到位置，以及实际执行哪些操作。本文以 Java 17 为基线，面向已了解接口、泛型、List、Iterator 和双向链表的读者，先分析操作成本，再实现一个教学用浏览历史模型。

## 知识清单与概念
- LL04-01：按操作比较 ArrayList 与 LinkedList，不使用“增删一律选链表”的口诀。
- LL04-02：LinkedList 下标循环遍历 O(n²)，迭代器遍历 O(n)。
- LL04-03：List 与 Deque 引用可用方法的区别，限定 Java 17。
- LL04-04：浏览历史状态建模、两端操作、清空前进分支、空历史保护。
- LL04-05：区分单次调用、均摊成本和组合操作总成本。

## 原理和复杂度
以下是常见 OpenJDK 实现的分析，不是所有 List 实现的统一保证。n 为列表长度；m 为前进历史长度。

| 操作 | ArrayList | LinkedList |
|---|---|---|
| get(i) | O(1) | 最坏 O(n)，从较近一端定位 |
| 尾部追加 | 均摊 O(1)，扩容时 O(n) | O(1) |
| 头部插入/删除 | O(n)，移动元素引用 | O(1) |
| 按中间下标插入/删除 | O(n) | O(n)，主要成本为定位 |
| 已定位迭代器处单个插入/删除 | 通常 O(n) | O(1) |
| 使用迭代器完整遍历 | O(n) | O(n) |

LinkedList 的修改成本要拆成定位成本和修改链接成本，不能忽略前者。下标遍历虽然从较近一端定位，定位成本累计仍为 O(n²)。迭代器保存当前位置并沿链接前进，不重复从列表端点寻找。

ArrayList 底层数组连续保存元素引用，不代表元素对象本身连续排列；LinkedList 节点还保存前后链接，有额外空间与间接访问成本。相同大 O 不代表相同实际耗时。对尾部收集数据、顺序读取或下标访问的普通列表场景，ArrayList 是合理起点；实际性能要求需结合负载验证。

## 接口与版本边界
Java 17 的 List 提供 get/set 等下标方法，不提供 addFirst；Deque 提供两端操作，但不提供 get(int)。LinkedList 同时实现 List 与 Deque。引用类型约束编译期可调用方法，具体实现决定操作成本。

Java 21 起 List 的接口体系增加了两端操作，因此不能把 Java 17 的“List 没有 addFirst”当成跨版本结论。本课该题严格按 Java 17 判断；Deque 的完整队列/栈语义留待后续课程。

## 迭代器示例
假设 numbers 是已存入 1～100 的 LinkedList<Integer>，并已导入 java.util.Iterator：
```java
Iterator<Integer> it = numbers.iterator();
int sum = 0;
while (it.hasNext()) {
    sum += it.next();
}
System.out.println(sum);
```
预期输出 5050，遍历 O(n)。next 是方法，必须带括号；泛型避免使用原始 Iterator 类型。

## 综合应用：浏览历史系统 V1.0
当前页单独保存；两份历史的尾部均表示最近页面。
- visit：当前页进入后退历史，切换当前页，清空旧前进路径。
- back：后退历史为空则不操作；否则保存当前页到前进历史，再从后退历史尾部取出页面。
- forward：执行对称操作，先判断前进历史为空的边界。

假设输入有效、非空；单线程内存示例，无网络请求和持久化。代码仅用已讲解内容；字段 final 是整理版本的补充：限制字段重新赋值，不限制列表内容修改，不作为本次验收依据。

### 可运行完整代码
保存为 BrowserHistory.java，使用 JDK 17：
`javac -encoding UTF-8 BrowserHistory.java`
`java BrowserHistory`

```java
import java.util.LinkedList;

public class BrowserHistory {
    private final LinkedList<String> backHistory = new LinkedList<>();
    private final LinkedList<String> forwardHistory = new LinkedList<>();
    private String currentPage = "首页";

    // 本教学示例约定 url 是有效的非空地址。
    public void visit(String url) {
        backHistory.addLast(currentPage);
        currentPage = url;
        forwardHistory.clear();
    }

    public void back() {
        if (backHistory.isEmpty()) {
            return;
        }
        forwardHistory.addLast(currentPage);
        currentPage = backHistory.removeLast();
    }

    public void forward() {
        if (forwardHistory.isEmpty()) {
            return;
        }
        backHistory.addLast(currentPage);
        currentPage = forwardHistory.removeLast();
    }

    public void printState() {
        System.out.println("当前=" + currentPage
                + ", 后退=" + backHistory
                + ", 前进=" + forwardHistory);
    }

    public static void main(String[] args) {
        BrowserHistory browser = new BrowserHistory();
        browser.visit("A");
        browser.visit("B");
        browser.back();
        browser.back();
        browser.back();
        browser.forward();
        browser.visit("C");
        browser.forward();
        browser.printState();
    }
}
```
预期输出（未声称已实际运行）：
```text
当前=C, 后退=[首页, A], 前进=[]
```

### 逐步状态
| 操作后 | 当前页 | 后退历史（头到尾） | 前进历史（头到尾） |
|---|---|---|---|
| 初始 | 首页 | [] | [] |
| visit A | A | [首页] | [] |
| visit B | B | [首页, A] | [] |
| 第一次 back | A | [首页] | [B] |
| 第二次 back | 首页 | [] | [B, A] |
| 第三次 back | 首页 | [] | [B, A] |
| 第一次 forward | A | [首页] | [B] |
| visit C | C | [首页, A] | [] |
| 第二次 forward | C | [首页, A] | [] |

第三次 back 与第二次 forward 不改变状态。

### 方法成本与内存
- visit：O(m + 1)，m 较大时记为 O(m)；清空前进历史是主要线性成本。
- back、forward：O(1)，包括空历史直接返回的分支。
- 空间：O(b + f)，b、f 分别为两份历史长度，不计网页内容及字符串本身的大小。
OpenJDK LinkedList.clear 会遍历节点清除 item、next、prev 引用，再重置列表状态。内存回收由 GC 后续处理，不能说 clear 当场释放每个节点内存。

## 常见坑与面试/开发重点
| 易错表述 | 准确表述 |
|---|---|
| 链表增删都是 O(1) | 已定位节点的链接修改 O(1)，按下标操作需计入定位 |
| 换成 List 引用就能快速 get | 接口不改变底层 LinkedList 的定位成本 |
| 访问 C 后本来就没有可前进页面 | 后退到 A 时仍有 B；访问 C 主动丢弃旧前进分支 |
| clear 释放每个节点 | clear 清除引用，节点是否及何时回收由 GC 决定 |

业务应用重点是先定义状态与操作规则，再选择结构。浏览历史例子与列表接口、多态、封装、泛型、迭代器及复杂度分析相衔接，不代表生产浏览器的全部行为。

## 小结
选择集合要从访问方式、位置定位、结构修改和实际内存成本出发。LinkedList 的迭代器遍历和端点操作是优势用法；按下标循环则会反复定位。浏览历史示例展示的是状态建模与端点操作，不需要提前引入框架。
